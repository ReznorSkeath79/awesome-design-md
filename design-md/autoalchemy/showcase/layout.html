Where v4.0 diverged from the plan — and why

  • Orchestration: moved to a single shared scheduler instead of one per region; per-region SLAs are now enforced by a single dependency graph, which is what made the 99.2% on-time figure possible.
  • Inventory aging: kept the manual source patch for two regions rather than blocking the cut-over — tracked as D-2 below.
  • Metric storage: a governed view layer rather than a physical warehouse table; query p95 fell more than projected as a result.
  • Alerting: shipped to the ops channel directly, not email — email batching hid the first 20 minutes of incidents.

07Design

One grammar, two surfaces

The review document and the operations dashboard share a single token set: warm paper, hard offset shadows, one orange accent, and numbers set apart in a mono display face.

Document surface

Reading is calm: warm paper, a faint dot grid, and orange reserved for the one thing that needs attention. Numbers run in a pixel/mono face so a dense page still scans.

Dashboard surface

Same tokens, denser grid. KPI tiles lift with a hard shadow, status colors stay strictly semantic — green / amber / red for ok / warn / crit and nothing else.

08Process log

How the quarter ran

  • Weeks 1-3: metric-definition workshops with each region; the definitional disagreements surfaced here, not in the build.
  • Weeks 4-8: shared pipeline built and shadow-run alongside the legacy roll-up for four weeks.
  • Week 9: dashboards migrated region by region, each reconciled to ±0.3% before the next started.
  • Week 10: cut-over, legacy roll-up retired; the first all-region morning report published.
⚠ A silent zero passed every validation check

One region reported a source extract with an empty inventory file. The schema was valid and the row count non-zero, so it passed; only the aging board's zero-total caught it. A per-region volume floor is now part of the ingest gate.
